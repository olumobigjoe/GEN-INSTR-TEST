# GLT 302 — General Instrumentation Online Test

A Streamlit-based online assessment application for **GLT 302 — GENERAL INSTRUMENTATION**, HND 1 Biochemistry, FPA.

## 1. Test Configuration

| Item | Configuration |
|---|---|
| Course | GLT 302 — GENERAL INSTRUMENTATION |
| Programme | HND 1 — BIOCHEMISTRY |
| Institution | FPA |
| Test date | 22 August 2026 |
| Overall access window | 9:00 AM – 11:00 AM |
| Individual test duration | 8 minutes |
| Question bank | 40 questions |
| Questions per student | 20 |
| Options per question | 3 |
| Question selection | Randomized once per student |
| Timer refresh | Every 10 seconds |
| Time zone | Africa/Lagos |
| Submission | One attempt per matriculation number |

## 2. Student Matriculation Numbers

The expected matriculation format is:

`FPA/BC/25/3-0001`

The application validates the matriculation number as a 16-character value.

The student allocation is:

- `FPA/BC/25/3-0001` through `FPA/BC/25/3-0155`
- Final student: `FPA/BC/25/3-0301`

This gives **156 authorized students** because the final student `0301` is additionally included.

### Batch allocation

| Batch | Students | Access time |
|---|---:|---|
| Batch 1 | 40 | 9:00 AM – 9:30 AM |
| Batch 2 | 40 | 9:31 AM – 10:00 AM |
| Batch 3 | 40 | 10:01 AM – 10:30 AM |
| Batch 4 | 36 | 10:31 AM – 11:00 AM |

Batch 4 contains the final student `FPA/BC/25/3-0301`.

> Note: `40 + 40 + 40 + 36 = 156`. Therefore, the stated batch sizes require 156 authorized students. The configuration deliberately includes `0301` as an additional final student.

## 3. Main Features

### Student portal

Students enter:

1. Full name
2. Gender
3. Matriculation number

The application:

- validates the matriculation format;
- checks whether the student is authorized;
- determines the student's batch;
- checks the current Lagos time;
- prevents students from accessing the test outside their assigned window;
- prevents duplicate attempts;
- creates a randomized 20-question test from the 40-question bank.

### Examination

Each student receives:

- 20 questions;
- 3 options per question;
- an individual 8-minute timer;
- a progress indicator;
- automatic submission when time expires.

The selected 20 questions remain fixed throughout the attempt. A Streamlit rerun must not generate a new set of questions.

### Lecturer dashboard

The lecturer dashboard provides administrative access for:

- question-bank verification;
- student results;
- batch summaries;
- result statistics;
- result CSV download;
- time analysis;
- score analysis;
- administrative monitoring.

## 4. Security

Sensitive information should not be placed directly in `app.py` or committed to GitHub.

Use Streamlit Secrets for:

- `QUESTION_BANK_JSON`
- `LECTURER_PASSWORD`
- `AUTHORIZED_STUDENTS_JSON`

The question bank should contain the correct answers, but the correct answers must never be displayed to students.

### Example secrets structure

```toml
LECTURER_PASSWORD = "YOUR_PRIVATE_PASSWORD"

AUTHORIZED_STUDENTS_JSON = '''
{
  "FPA/BC/25/3-0001": "Batch 1",
  "FPA/BC/25/3-0002": "Batch 1"
}
'''

QUESTION_BANK_JSON = '''
[
  {
    "id": 1,
    "question": "Example question",
    "options": {
      "A": "Option A",
      "B": "Option B",
      "C": "Option C"
    },
    "correct_answer": "A"
  }
]
'''
```

Do not publish the real password, student list, or question bank in a public repository.

## 6. Installation

Create a Python environment and install the dependencies:

```bash
pip install -r requirements.txt
```

Run the application locally with:

```bash
streamlit run app.py
```

The application will open in the Streamlit browser interface.

## 7. Streamlit Cloud Deployment

1. Create a GitHub repository.
2. Add:
   - `app.py`
   - `requirements.txt`
   - `README.md`
3. Do **not** commit private secrets.
4. Create a Streamlit Cloud application from the repository.
5. Open the application's **Secrets** settings.
6. Add the required:
   - `LECTURER_PASSWORD`
   - `AUTHORIZED_STUDENTS_JSON`
   - `QUESTION_BANK_JSON`
7. Deploy the application.
8. Test the application before distributing the student URL.

## 8. Question Bank

The application is designed for a private 40-question GLT 302 question bank.

Each question must contain:

- an ID;
- the question text;
- exactly three options;
- the correct answer.

Recommended structure:

```json
{
  "id": 1,
  "question": "What is measurement?",
  "options": {
    "A": "The process of finding the amount or magnitude of a physical quantity",
    "B": "The process of repairing a measuring instrument",
    "C": "The process of converting electrical energy into mechanical energy"
  },
  "correct_answer": "A"
}
```

The bank should contain exactly 40 valid questions.

## 9. Timer Behaviour

The individual examination duration is:

**8 minutes = 480 seconds**

The application calculates elapsed time from the stored examination start time rather than resetting the timer during Streamlit reruns.

The active examination refreshes every 10 seconds.

The refresh is used to update the timer without creating a new question set.

When the timer reaches zero:

- the student's current answers are scored;
- the attempt is saved;
- the test is closed;
- the result page is displayed.

## 10. Duplicate Submission Protection

Each matriculation number is permitted only one successful attempt.

Before starting the test, the application checks the results data for the matriculation number.

The application also checks during result saving so that a student cannot simply submit a second attempt after the first submission has been recorded.

## 11. Time Seconds

The results data includes a permanent numeric:

`Time Seconds`

This field is intended for reliable time analysis.

For example:

```text
08:25
```

is stored/analyzed as:

```text
505
```

The application should also be able to normalize legacy `MM:SS` and `HH:MM:SS` values when they exist in older results.

This avoids sorting times alphabetically, where values such as `10:00` could otherwise appear before `2:00`.

## 12. Time Zone

All test access calculations use:

`Africa/Lagos`

The application must not depend on the Streamlit server's local time zone.

The displayed batch times are Nigeria/Lagos time.

## 14. Important Operational Notes

### Do not expose the answer key

The question bank must remain in Streamlit Secrets. Students should only receive question text and answer choices.

### Do not modify the question selection during reruns

A new random selection must only be created when a student starts a new authorized attempt.

### Do not use the server's local clock

Always use the Lagos timezone for batch access decisions.

### Do not manually create student attempts

The application should determine the batch from the authorized student allocation.
